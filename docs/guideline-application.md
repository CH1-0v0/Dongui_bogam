# 첨부 개인정보 안내서 반영 기준

참고 자료는 사용자가 첨부한 「알기쉬운 개인정보 처리 동의 안내서」와 「개인정보 처리 통합 안내서(2025.7.)」입니다. 원문 파일은 저장소에 포함하지 않았습니다. 아래 쪽수는 안내서에 인쇄된 쪽수 기준입니다. 안내서는 문서 작성 참고 자료로 사용했습니다.

| 작성 기준 | 참고 위치 | 구현 |
| --- | --- | --- |
| 목적·항목·기간·거부권 및 불이익을 명확하게 고지 | 알기쉬운 안내서 동의서 작성 방법 및 서식(31~33쪽), 통합 안내서 동의 관련 설명 | 동의 유형별 표와 거부 안내, 최종본에서 각 구분의 실제 생성 문서에 목적·항목·기간·거부권·불이익이 있는지 체크 |
| 민감정보·고유식별정보 등 별도 동의 | 알기쉬운 안내서 31~33쪽, 통합 안내서 47쪽 | 개인정보 분류별 독립된 동의·미동의 선택란. 일반 필수/선택, 목적 외 이용, 제공, 마케팅도 별도 점검 |
| 중요 내용 식별 | 통합 안내서 116쪽·123쪽의 중요 내용 표시 기준 | 일반 개인정보 항목명은 보통 글씨. 민감·고유식별정보, 보유기간, 제공받는 자와 제공받는 자의 목적, 마케팅 연락 사실을 동의 문서에서 강조 |
| 동의 없이 처리하는 사항의 안내 | 알기쉬운 안내서 31~33쪽의 고지 예시 | 동의와 구분해 문서 하단에 고지. 실제 근거와 조건이 같으면 유형을 넘어서 통합하고 특별한 정보만 강조 |
| 주민등록번호는 동의만으로 처리 불가 | 통합 안내서 주민등록번호 처리 제한 설명, 개인정보 보호법 제24조의2 | 동의서 유지 선택 제외, 적법한 별도 근거 확인 전 다음 단계 제한 |
| 계약·업무 법령이 특별 요건을 자동 충족하지 않음 | 통합 안내서 47쪽, 원천징수 설명 71쪽 | 실제 업무 법령을 검색하고 민감·고유·주민등록번호 권한은 별도 확인. 소득세법의 원천징수 의무만으로 주민등록번호 권한을 추정하지 않도록 AI 요청에 명시 |

이전 안내서의 중요 내용 글자 크기 권고와 2025년 안내서의 식별 가능한 표시 기준을 함께 고려했습니다. PDF는 일반 10.5pt / 중요 12.6pt, HWPX는 일반 10pt / 중요 12pt와 파란색·굵기를 사용합니다. 고지 전용 표는 사용자 요청에 따라 민감정보·고유식별정보 항목만 강조합니다.

## 법령 적용 흐름

1. 일반 수집 / 목적 내 제공 / 목적 외 이용·제공을 선택합니다.
2. 개인정보 보호법상 근거를 선택합니다. 처리 상황 안에 해당 정보가 있으면 제23조·제24조·제24조의2 관련 근거도 선택할 수 있습니다.
3. 법령 근거가 필요한 경우 실제 업무 법령과 조·항·호를 국가법령정보센터에서 선택합니다. AI 자동 검색도 업무 법령을 찾도록 요청합니다.
4. 적용할 항목을 여러 개인정보 유형에 걸쳐 선택합니다. 일반 법령 근거에 민감정보·고유식별정보·주민등록번호를 함께 적용할 때는 필요한 별도 근거를 체크합니다. 서버는 선택한 모든 근거를 원문으로 확인하며 일부가 실패하면 전체 등록을 완료하지 않습니다.
5. 담당자가 근거와 범위를 확인해 적용합니다. 직접 등록의 AI 검토는 선택사항이고 부정적인 답변이 등록을 차단하지 않습니다. AI 검색 결과에는 추가 AI 검토를 요구하지 않습니다.

적용 법령 수정 버튼은 내용을 펼치기 전에도 보입니다. 한 번 등록한 묶음을 수정하면 기존 묶음을 교체해 중복 등록을 방지합니다.

## 검증 범위

`tests/guideline-flow.cjs`는 합성 법령으로 혼합 유형 적용·별도 권한·주민등록번호 동의 제외·묶음 수정·동의/고지 분리·편집 저장·7가지 동의 구분의 실제 기재 여부·제목 파일명을 확인합니다. 서버 테스트는 여러 근거의 원자적 검증과 잘못된 처리 상황을 검사합니다. `tests/check_guideline_exports.py`는 PDF 및 HWPX의 강조·간격·테두리·서명 구조를 검사합니다.

자동 점검은 기재 여부와 구조를 확인합니다. 개별 처리의 적법성·조문 해석·동의 문구의 충분성은 담당자가 판단해야 합니다. 이 환경에는 실제 API 키가 없으므로 실제 인증 및 AI 판단 정확도는 검증하지 않았습니다. 한글 프로그램에서의 최종 배치도 내려받은 파일로 확인해야 합니다.

업데이트 시 기존 `.env`를 새 폴더의 `server.py` 옆으로 복사하고 서버를 재시작한 뒤 Ctrl+F5로 새로고침합니다. `/api/status`에서 `apiVersion: 8`을 확인하세요. API 연결 방법은 [법령 API 설정](step3-api.md)을 참고하세요.

## 로컬 실제 API 확인

`.env`에 서버 전용 `LAW_API_OC`와 `OPENROUTER_API_KEY`를 설정합니다. 파일 내용이나 키를 브라우저 코드에 넣지 않습니다. `OPENROUTER_MODEL=openai/gpt-oss-120b`를 사용할 수 있습니다. 기존 키 파일은 공유하거나 커밋하지 마세요.

```sh
python tests/live_api.py
python tests/live_api.py --search
python tests/live_api.py --review
```

첫 명령은 법령 API 원문 조회, 두 번째는 실제 AI 검색, 세 번째는 직접 등록의 선택적 AI 검토·적용 요청 경로를 확인합니다. AI 명령에는 사용료가 발생할 수 있습니다. `--review`는 검토 의견이 부정적이어도 담당자 적용 요청을 차단하지 않는지 확인하며 문서 데이터를 저장하지 않습니다.

브라우저에서는 수집 목적을 실제 업무에 맞게 구체적으로 입력한 뒤 자동 검색 결과에 업무 관련 법령이 나오는지 확인하세요. 소득 지급·원천징수 업무라면 소득세법 등의 원문을 확인하고, 주민등록번호는 그 번호의 처리를 허용하는 구체적인 조문을 따로 확인해야 합니다. 직접 등록에서는 일반 수집 → 법령 근거 → 업무 법령 검색 → 조·항·호 → 적용 항목 → 필요한 별도 허용 근거 → ⑤ 담당자 확인 순서로 진행합니다.

[처리 상황별 법령 등록 화면 — 합성 데이터](previews/context-law-picker.png)

후속 화면 요청에 따라 목적 외 이용·제공과 마케팅의 문서는 개인정보 유형을 한 표로 묶고 해당 처리의 동의란을 하나씩 표시합니다. 수집의 일반 개인정보 필수·선택은 한 표의 별도 행·별도 동의란을 사용합니다. 마케팅 연락 사실은 기본 글자 크기의 굵은 파란 글씨로 표시하고, 고지사항의 보유기간도 강조합니다.

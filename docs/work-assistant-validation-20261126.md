# 업무 대화 작성 경로 검증 (2026-11-26)

## 변경 범위

업무 설명 입력으로 시작하는 선택 경로를 추가했습니다. 수집·이용을 먼저 확인하고 목적 외 이용·제3자 제공을 별도로 정리한 뒤 기존 1~3단계의 상태를 채워 4단계로 이동합니다. 기존 생성·빠른 생성 버튼은 원래 경로를 유지합니다. Python과 Cloudflare 모두 같은 정책과 검증 절차를 사용하며 DB는 추가하지 않았습니다.

기관명·짧은 제목·안내문·필수/선택 거부 문구를 4단계에서 편집할 수 있습니다. 자동 문구를 직접 수정한 경우 재진입으로 덮어쓰지 않습니다. 빠른 생성 8개 설정은 design/quick-templates.json으로 분리했고 CSV·JSON 검토 파일도 제공했습니다.

## 자동 검증

Worker/실제 workerd 및 대화 모듈 72개, Python 75개, 근거 규칙·상태·요약 단위 검사 21개가 통과했습니다. 출처 발췌가 없는 항목·기간 제외, 기간 대상 재검토, 주민등록번호의 이중 근거 요구, 임상 정보 보수적 분류, 서명 위조·맥락 변경 거부, 이전 답변 유지, 잘못된 항·호의 전체 조문 재조회, CSRF·요청 한도·본문 제한을 검사합니다.

합성 API를 사용한 브라우저 검사는 대화 왕복, 추가 제공 업무, 4단계 바로 이동, 기존 수동 경로, 기본 문구와 사용자 수정 보존, 선택 거부 문장, 미확인 필드 보완, 전송 버튼 오른쪽 정렬, 1440/768/390px에서 가로 넘침이 없는 것을 확인했습니다. 기존 항목 분류 제한·주민등록번호 필수 고정·새 문서 시작·법령 선택·PDF/HWPX 출력 회귀 검사도 통과했습니다. 고지 전용/혼합 서식의 PDF·HWPX 구조 검사는 유지됩니다.

## 실제 운영 API 시험

실제 개인 식별값 없이 가상의 의료기관이 외래 진료기록부 작성·보존을 하는 업무를 입력했습니다. source 검색, 공식 법령 조회, AI 발췌·검토를 실제로 호출했습니다.

- 최종 왕복 시험의 첫 응답: HTTP 200, 71초. 주소·성명·연락처와 진료 관련 항목 10개, 법정 보유기간 10년을 정리했습니다. 일부 공식 조회 실패가 있었고 주민등록번호는 별도 요건이 확인되지 않아 자동 입력에서 제외했습니다.
- 후속 답변: HTTP 200. 기존 항목과 10년을 유지했고, 일반 실명 환자라는 업무 맥락을 추가한 뒤 일반 근거와 주민등록번호 별도 허용 근거가 함께 확인된 주민등록번호를 포함했습니다. 서명된 원문 참조와 이전 사실을 재사용했습니다.
- 실제 원문 근거에는 의료법 제22조, 의료법 시행규칙 제14조·제15조, 의료법 시행령 제42조의2가 포함됐습니다. 후보의 항·호가 부정확한 경우 존재하는 전체 조문을 다시 공식 조회하고 그 본문으로 검토했습니다. 없는 조문 번호를 보충하지 않습니다.
- 초기 시험에서 발견한 보존기간 발췌 실패, 후속 답변의 이전 항목 누락, 가족력·의료서술 항목의 일반 분류를 보완했습니다. 마지막 분류 보완은 단위 검사로도 확인했습니다.

이 시험은 위 입력에 대한 관측이며 다른 업무의 정확도나 항상 같은 항목이 나오는 것을 보증하지 않습니다. 법령 조회에 실패했거나 적용 요건이 부족한 정보는 임의로 채우지 않고 추가 질문·미확인 상태로 남깁니다. 서류 종류·처리 주체·불가피성 등 실제 업무 조건은 담당자가 확인해야 합니다.

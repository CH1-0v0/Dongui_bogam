# 3단계 법령 검색: 실행, 키 보관, 배포와 검증

변경 브랜치: `feature/step3-verified-law-search`. 기존 1·2단계의 분류 방식과 문서 편집·출력 기능은 유지하고, 3단계의 근거 검색·선택 및 그 선택이 4단계에 반영되는 규칙을 수정했습니다.

## 검색 흐름

1. 브라우저가 항목명·처리 목적·제공받는 기관·처리 유형을 같은 사이트의 `/api/law/search`에 보냅니다. 기관명과 API 키는 AI 요청 본문에 포함하지 않습니다.
2. 서버가 OpenRouter의 `openai/gpt-oss-120b`로 최대 4개의 법령·조·항·호 후보와 적용 검토 이유를 요청합니다. 모델 변경은 서버의 `OPENROUTER_MODEL`로만 합니다.
3. 서버가 국가법령정보센터 `lawSearch.do`에서 **정식 법령명**을 정확히 대조하고, 미래 시행본을 제외한 현행본의 `법령일련번호`를 얻습니다. `lawService.do?MST=...`로 해당 본문을 조회합니다.
4. 실제 존재하는 조·항·호만 통과시킵니다. 표시할 원문은 AI 문구가 아니라 API 본문에서 추출합니다. 연결되는 개인정보 보호법 조·항·호도 별도로 조회합니다. 실패 후보는 사유와 함께 제외합니다.
5. 사용자가 처리 근거와 적용할 항목을 선택하고 적용 요건을 확인합니다. 채택은 자동으로 하지 않습니다. ‘원문 확인’은 조문의 존재와 인용 확인이며, 해당 업무에서 동의 없이 처리해도 된다는 법률 판단을 보증하지 않습니다.

모델은 일반 지식으로 후보를 제시하고 서버가 공식 API에서 검증합니다. OpenRouter에 별도의 웹 검색 플러그인을 붙이거나 AI가 임의 URL에 접속하게 하지는 않습니다. 모델이 기억하지 못한 법령은 제안에서 빠질 수 있으며, **법령 검색·근거 추가 → 공식 검색 결과 → 조·항·호 선택 → 선택한 조문 가져오기**으로 보완할 수 있습니다. 원문 검증 후의 설명은 ‘AI가 제안한 적용 검토 이유’이며 원문 기반 2차 AI 심사를 수행했다고 표시하지 않습니다.

검색 방식의 ‘화면 시연’은 서버에서 `LAW_SEARCH_DEMO=true`일 때만 제공합니다. 실제 호출 실패 시 시연으로 자동 전환하지 않습니다.

## 동의서와 고지사항 구분

| 3단계에서 선택한 근거 | 연결 조항 | 4단계 반영 |
| --- | --- | --- |
| 동의를 받는 경우 | 개인정보 보호법 제15조 제1항 제1호 | 동의서 유지. 채택하지 않아도 됨 |
| 법령 근거 수집 | 제15조 제1항 제2호 + 구체적 개별 법령 조문 | 원문·적용 요건 확인 후 선택 항목만 고지 |
| 공공기관 소관 업무 수행 | 제15조 제1항 제3호 + 법령상 소관 업무 근거 | 원문·적용 요건 확인 후 고지 |
| 계약 체결·이행 등을 위해 필요한 경우 | 제15조 제1항 제4호 | 필요성과 적용 요건 확인 후 고지 |
| 제3자 제공 | 제17조 제1항 제1호 또는 제2호 | 동의 근거는 동의서 유지, 법령 근거는 별도 확인 |
| 목적 외 이용·제공 | 제18조 제2항 제1호 또는 제2호 | 별도 동의와 다른 법률의 특별한 규정을 구분 |
| 민감정보·고유식별정보 허용 | 제23조·제24조 제1항 제2호 | 별도 처리 허용 근거. 일반 수집·제공 근거도 충족해야 고지 |
| 주민등록번호 허용 | 제24조의2 제1항 제1호 | 구체적 처리 허용 근거와 일반 수집·제공 근거 모두 필요 |

‘개인정보 보호법 제15조 제1항’ 전체처럼 동의 근거가 포함된 포괄 인용이나 제15조 제1항 제1호를 채택했다는 이유로 고지로 바뀌지 않습니다. 법령 근거 수집에서 제15조 제1항 제2호 자체만 입력하는 것도 개별 업무의 구체적인 처리 근거 확인을 대신하지 않습니다.

동의 없는 처리의 모든 예외를 자동 지원하는 것은 아닙니다. 이번 UI에서 제공하는 유형은 `law-basis.js`와 `basis-rules.json`에 명시한 범위입니다. 법령 개정으로 번호·요건이 바뀌면 표와 코드의 규칙을 함께 검토해야 합니다. 법령 API가 조문 존재를 확인해도 라벨의 법적 해석을 자동 갱신하지는 않습니다.

같은 항목이라도 수집 허용 근거가 제3자 제공이나 목적 외 제공까지 자동 허용하지 않습니다. 민감정보 등의 별도 허용 조항은 일반 처리 근거를 대체하지 않습니다. 인용의 법령명·조·항·호·원문·연결 근거를 수정하면 기존 확인 상태와 요건 확인이 해제되고 재조회해야 합니다.

## 1. 인증정보 준비

- OpenRouter: <https://openrouter.ai/settings/keys>에서 API 키를 만들고 사용 예산을 설정합니다. 모델 ID는 `openai/gpt-oss-120b`입니다. 실제 사용 시 제공 여부와 가격을 확인하세요.
- 국가법령정보센터: <https://open.law.go.kr/>의 공동활용/Open API 이용 신청과 승인을 진행합니다. 승인된 `OC`를 `LAW_API_OC`에 넣습니다. 일반적으로 신청 이메일의 `@` 앞부분을 쓰지만, 승인 안내를 우선합니다. 별도 법령 조회 권한 또는 서버 IP 등록이 필요한지는 본인의 승인 조건에 따라 확인하세요.

API 키와 OC는 채팅·소스코드·브라우저 입력창에 붙여 넣지 마세요. 이 앱은 키를 브라우저에서 받지 않습니다.

## 2. 배포 전: 로컬 파일에 보관

저장소 디렉터리에서 실행합니다.

```sh
cp .env.example .env
chmod 600 .env
```

`.env`를 **로컬 편집기**로 열어 값을 입력합니다. 실제 키를 명령줄 인자로 쓰지 마세요.

```dotenv
OPENROUTER_API_KEY=여기에_실제_키를_로컬에서만_입력
OPENROUTER_MODEL=openai/gpt-oss-120b
LAW_API_OC=승인된_OC
HOST=127.0.0.1
PORT=3000
LAW_SEARCH_DEMO=false
```

```sh
python3 server.py
```

로컬에서 실행한 경우에만 `http://127.0.0.1:3000`으로 접속합니다. 키는 서버 프로세스가 읽으며 브라우저에는 전달하지 않습니다. 서버 프로세스의 환경변수가 이미 있으면 파일보다 우선합니다. 파일 변경 후 서버를 재시작하세요.

`.gitignore`는 `.env`와 파생 환경 파일을 제외하며, 서버의 정적 파일 허용 목록은 `.env`, `.git`, 서버 코드, 테스트, 문서 등 비공개 파일을 HTTP로 제공하지 않습니다. 키를 localStorage·프런트엔드 번들·HTML에 넣지 않습니다. `.env.example`만 커밋합니다.

더 분리하려면 저장소 **밖의 개인 폴더**에 파일을 두고 다음처럼 경로만 지정합니다.

```sh
APP_ENV_FILE=/본인의/비공개/경로/dongui.env python3 server.py
```

저장소를 Python의 `http.server`나 다른 범용 정적 서버로 직접 공개하면 `.env`가 노출될 수 있습니다. 실제 키가 있는 디렉터리에는 그런 서버를 실행하지 말고, 제공한 `server.py`를 사용하세요. 과거에 키를 커밋하거나 공개했다면 파일 삭제만으로 끝내지 말고 해당 키를 폐기·재발급해야 합니다.

## 3. 클라우드에서 미리보기

현재 서버는 **3000 포트**로 실행합니다. 클라우드에서는 `HOST=0.0.0.0`으로 바인딩해야 합니다. 환경 설정의 **HTTP Previews에 3000 추가 → Apply to this chat** 후 생성된 인증 미리보기 URL로 접속합니다. 클라우드의 localhost는 사용자의 컴퓨터 주소가 아닙니다.

실제 API를 클라우드에서 테스트하려면 환경 설정에서 외부 접근을 허용해야 합니다.

- `openrouter.ai` — AI API 및 모델 목록
- `www.law.go.kr` — DRF 법령 검색·본문 API
- `open.law.go.kr` — 공식 API 안내

도메인 허용은 초안에 저장되어도 현재 인스턴스에 적용되기 전에는 작동하지 않습니다. 환경 설정에서 검토·적용한 뒤 재시도하세요. 키를 환경 설정의 서버용 비밀 환경변수 또는 비공개 파일로 전달하세요. 공개 환경변수로 등록하지 마세요. 프록시용 비밀 바인딩을 쓰는 플랫폼에서는 `OPENROUTER_API_KEY`를 `openrouter.ai`에만 허용하도록 설정합니다. `LAW_API_OC`는 공식 API에서 쿼리 인증에 쓰이므로 플랫폼의 치환 지원 여부가 불명확하면 서버 전용 비공개 파일/런타임 비밀변수로 설정하세요.

시연 화면은 키 없이 사용할 수 있습니다. 실제 API 확인 배지가 붙은 스크린샷이라도 자동 테스트의 가상 응답으로 만든 경우 실 API 성공 증거가 아닙니다.

## 4. 실제 API 테스트

먼저 서버 없이 법령 API만 확인합니다. 스크립트는 동일한 `.env` 또는 `APP_ENV_FILE`을 읽습니다.

```sh
python3 tests/live_api.py
```

이 명령은 개인정보 보호법 제15조 제1항 제1호의 현행 원문과 연결 조항을 실제 API로 조회합니다. 필요한 설정이 없으면 `미실행`과 변수명만 출력하고 종료 코드 2를 반환합니다. 값은 출력하지 않습니다.

OpenRouter까지 포함한 검색은 다음 명령입니다. 모델 호출 1회가 발생하며 사용료가 청구될 수 있습니다.

```sh
python3 tests/live_api.py --search
```

모델 목록에서 설정한 ID가 있는지 확인한 뒤 **AI 후보 생성 → 개별 법령 원문 대조 → 개인정보 보호법 연결 조항 확인**을 실행합니다. 통과한 후보 수만 출력합니다. 0건이면 성공으로 처리하지 않습니다. API 인증·크레딧·한도·네트워크 오류를 구분하여 확인하세요.

화면 테스트는 다음 순서로 진행합니다.

1. 홈에서 **예시로 시작**, 2단계를 거쳐 3단계로 이동합니다.
2. **실제 API 검색 → AI로 법령 근거 찾기**를 누릅니다. 동의 조항만 나오면, 다른 개별 법령이 반드시 있다는 의미는 아닙니다.
3. 후보의 조문 내용, 원문 링크, 시행일, 확인 시점과 연결 조항을 검토합니다.
4. **적용 항목·처리 근거 검토**에서 항목을 선택합니다. 동의 근거를 채택하고 4단계로 이동했을 때 동의란이 유지되는지 확인합니다.
5. 개별 법령 근거를 선택하면 원문과 요건 확인을 마친 뒤에만 저장되는지, 4단계에서 선택한 항목만 고지사항에 표시되는지 확인합니다.
6. 수집용 근거가 제공용 근거를 대신하지 않는지, 민감정보 등의 별도 허용 근거만으로 고지로 바뀌지 않는지도 확인합니다.

법령 검색·근거 추가는 AI 호출 없이 법령 API만으로 검색하고 원문을 가져옵니다. 검색에는 LAW_API_OC가 필요하며 OpenRouter 키는 필요하지 않습니다. 조문은 자유 입력하지 않고 API가 반환한 목록에서 선택합니다. 계약 등 법적 근거는 소명할 실제 사실관계가 있을 때 선택하세요.

## 5. 키 없이 자동 테스트

```sh
node --test tests/basis.test.cjs
python3 -m unittest discover -s tests -p 'test_*.py' -v
```

정책 테스트는 동의 조항, 포괄 인용, 계약, 처리 유형, 민감정보·고유식별정보·주민등록번호의 추가 요건을 확인합니다. Python 테스트는 외부 응답을 **가상 XML/JSON**으로 대체하여 법령명 정확 일치, 없는 조문 제외, 미래 시행본 제외, AI 문구 대신 원문 사용, 인증정보 비노출, HTTP 파일 차단 및 요청 검증을 확인합니다. 실제 API 이용 성공을 증명하지는 않습니다.

브라우저 회귀 검증에는 Node.js와 Playwright, Chromium이 필요합니다. 준비된 클라우드 환경에는 이미 설치되어 있습니다. 일반 개발 컴퓨터에서는 저장소 밖에 테스트 도구를 설치할 수 있습니다.

```sh
mkdir -p ../dongui-browser-tools
npm install --prefix ../dongui-browser-tools playwright
../dongui-browser-tools/node_modules/.bin/playwright install chromium
```

`CHROMIUM_PATH`에는 설치한 Chromium 실행파일 경로를 지정합니다. Linux 시스템 Chromium은 보통 `/usr/bin/chromium`입니다. Playwright 설치 경로는 아래 명령으로 확인할 수 있습니다.

```sh
NODE_PATH=../dongui-browser-tools/node_modules node -e "console.log(require('playwright').chromium.executablePath())"
```

한 터미널에서 키 없이 시연 서버를 실행합니다.

```sh
LAW_SEARCH_DEMO=true python3 server.py
```

다른 터미널에서 실행합니다. 실제 키가 설정된 서버에서는 첫 번째 ‘설정 없음’ 검증 대신 별도 테스트용 서버를 쓰세요.

```sh
# 현재 클라우드 (이미 설치된 도구 사용)
node tests/browser.cjs
# 별도 설치 도구를 사용하는 로컬 예시
NODE_PATH=../dongui-browser-tools/node_modules CHROMIUM_PATH=/본인/Chromium/실행경로 node tests/browser.cjs
```

브라우저 검증은 시연 검색, 동의 유지, 항목별 고지, 인용 수정 시 검증 해제, 모바일 가로 넘침, PDF·HWPX 다운로드를 확인합니다. 고지 분기 확인에는 테스트 브라우저 내부에서만 가상 API 응답을 사용합니다. 결과 스크린샷과 다운로드 파일은 Git에서 제외되는 `.test-output/`에 저장합니다.

## 6. 배포 시: 서버 비밀 설정으로 이전

이 앱은 API 키가 필요한 기능을 추가했으므로 정적 호스팅만으로는 실제 검색을 제공할 수 없습니다. Python 백엔드를 실행할 수 있는 호스팅이나 같은 구조의 서버리스 백엔드가 필요합니다. 제공한 서버는 개발·미리보기용 기본 서버입니다.

1. 배포 플랫폼의 **Secret/Environment Variables**에 `OPENROUTER_API_KEY`, `LAW_API_OC`를 비밀 값으로 등록합니다. `OPENROUTER_MODEL=openai/gpt-oss-120b`, `HOST=0.0.0.0`, `PORT=플랫폼에서 지정한 포트`, `LAW_SEARCH_DEMO=false`도 설정합니다. 프런트엔드용 `VITE_`·`NEXT_PUBLIC_` 접두사는 쓰지 않습니다.
2. `.env`는 Git이나 배포 이미지에 넣지 않습니다. 기존 서버 환경변수를 쓰므로 배포 파일에 키를 복사할 필요가 없습니다.
3. 실행 명령은 `python3 server.py`입니다. 실서비스에서는 플랫폼의 HTTPS 프록시와 사용자 인증을 앞단에 두고, 운영 HTTP 서버로 `Handler`를 호스팅하거나 해당 플랫폼의 Python API 런타임에 옮겨야 합니다. 개발용 `http.server`를 인터넷에 그대로 노출하는 배포는 권장 구성에 포함하지 않습니다.
4. 외부 요청 URL/응답·Authorization 헤더를 로깅하지 않도록 설정합니다. 특히 법령 API의 OC는 쿼리로 전달되므로 프록시의 전체 URL 로그에도 남기지 않게 해야 합니다.
5. 프록시에서 원래 `Host` 헤더를 유지하고 같은 도메인의 `/api/*`를 백엔드로 연결하고 나머지 정적 파일만 허용 목록으로 제공합니다. 브라우저 개발자 도구에서 OpenRouter/DRF로의 직접 요청이 없고 `/api/status`는 설정 여부만 반환하며 `.env` 요청은 404인지 확인합니다.
6. 배포 후 위 실제 API 테스트와 항목별 화면 검증을 반복합니다. 서버의 분당 6회·동시 2요청 제한은 기본 비용 방어이며, 공개 서비스에는 사용자별 인증·이용 한도와 영구적 비용 제한을 배포 플랫폼에서 추가해야 합니다.

OpenRouter 요청은 데이터 수집을 허용하지 않는 제공자로 라우팅하도록 설정했습니다. 이 조건이나 JSON 응답을 지원하는 제공자가 없으면 요청이 실패할 수 있습니다. 실제 사람의 이름·전화번호·주민등록번호를 넣지 말고 항목명과 처리 맥락만 사용하세요. 기본 형식 차단이 모든 개인정보를 탐지하는 것은 아닙니다.

## 로컬에서 Failed to fetch가 나타났을 때

이 문구만으로 원인을 확정할 수 없습니다. 최신 버전은 서버 연결 실패, 시간 초과, API 오류와 이전 버전 서버를 구분하여 안내합니다.

1. 기존 터미널에서 Ctrl+C로 서버를 종료합니다. ZIP을 다시 받을 때 `.env`는 따로 보관하고 **최신 프로젝트 폴더의 server.py 옆**에 둡니다. 키를 터미널이나 채팅에 출력하지 않습니다.
2. 최신 폴더에서 `python server.py`를 실행하고 터미널을 닫지 않습니다. 주소창에서 `http://127.0.0.1:3000/api/status`를 엽니다. `app: dongui`, `apiVersion: 2`가 있어야 최신 서버입니다. `aiConfigured`, `lawConfigured`는 값이 설정되어 있는지만 뜻하며 인증 성공을 보증하지는 않습니다.
3. 홈으로 돌아와 Ctrl+F5로 새로고침합니다. `file:///.../index.html`이나 다른 정적 서버로 열지 않습니다.
4. ‘법령 검색·근거 추가’ 검색은 LAW_API_OC만으로 확인할 수 있습니다. AI 검색은 OPENROUTER_API_KEY도 필요합니다.
5. 실패하면 화면 오류 문구와 터미널의 `API POST /api/law/... 상태코드`를 확인합니다. 이 로그에는 키·OC·요청 본문이 포함되지 않습니다. `/api/status`도 열리지 않으면 외부 API보다 로컬 서버 실행 상태를 먼저 확인합니다.

Windows UTF-8 BOM이 있는 환경 파일도 읽습니다. 파일명은 `.env.txt`가 아닌 `.env`여야 합니다. 기존 서버가 계속 실행 중이면 새 파일을 다운로드해도 새 API가 적용되지 않으므로 반드시 종료 후 재시작하세요.

# 3단계: 개인정보 유형별 근거 검토와 적용

3단계는 **AI가 찾은 법령: 항목 선택 → 담당자 확인 → 적용**, **직접 추가한 법령: 항목 선택 → AI 검토(선택) → 담당자 확인 → 적용**하는 화면입니다. 조문이 검색되었다는 이유만으로 동의서가 고지사항으로 바뀌지 않습니다.

## 화면 사용 순서

일반 개인정보(필수)·선택 동의·민감정보·고유식별정보·제3자 제공 등의 대분류마다 목적을 작게 표시하고, 그 아래에 해당 유형의 법령과 적용 결과를 함께 표시합니다. AI 결과와 적용 화면을 위아래에 중복하여 나열하지 않습니다.

### AI 법령에서 적용

1. ‘AI로 적용 근거 찾기’를 누릅니다. 항목명, 처리 목적, 제공받는 기관, 개인정보 유형만 서버를 통해 OpenRouter에 보냅니다. 실제 개인정보 원문과 키는 보내지 않습니다.
2. 각 대분류 아래에 나타난 법령들을 비교합니다. 법령이 여러 개라도 모두 적용되는 것이 아닙니다.
3. 사용할 법령에서 ‘이 법령의 적용 항목 선택’을 누릅니다. 같은 유형에서 아직 선택하지 않은 다른 법령은 숨깁니다. 필요하면 ‘다른 법령 보기’로 다시 확인할 수 있습니다. 이미 다른 항목에 적용한 법령은 유지합니다.
4. 적용할 항목만 체크하고, 해당 근거의 요건을 실제로 충족하는지 검토합니다. 아무 항목도 자동으로 체크하지 않습니다. AI의 항목별 의견은 검토 참고용이며 최종 적용 판단을 대신하지 않습니다.
5. AI가 찾아 공식 원문을 확인한 법령에는 별도의 AI 검토 단계를 표시하거나 호출하지 않습니다. 담당자 확인을 마친 뒤 ‘검토한 항목에 이 근거 적용’을 누릅니다. 적용한 법령은 삭제하지 않고 ‘적용됨’ 표시와 함께 접습니다. 다시 펼쳐 적용 항목을 바꿀 수 있습니다.
6. ‘이 법령 선택 안함’을 누르면 현재 목록에서 숨깁니다. 이미 적용한 법령이라면 적용도 해제합니다. ‘검토할 법령’을 접었다 다시 펼치면 해당 법령을 다시 확인할 수 있습니다. 같은 맥락에서 재검색해도 기존 법령과 적용 내역은 보관합니다.

### 직접 근거를 선택하여 적용

‘법령·처리 근거 직접 추가’를 누르면 접을 수 있는 입력 영역이 열립니다.

1. **개인정보 유형**을 선택합니다. 직접 추가에서는 선택 항목을 제외합니다. 선택 항목은 이 앱에서 동의서로 작성하는 흐름이며, 법률 일반의 모든 예외를 부정하는 의미는 아닙니다.
2. **개인정보 보호법의 동의 외 근거**를 먼저 선택합니다. 동의는 별도 법령으로 추가하지 않습니다. 근거를 적용하지 않은 항목은 기본적으로 동의서로 진행합니다.
3. 계약 이행, 급박한 생명·신체·재산 보호, 정당한 이익, 긴급한 공공 안전 등의 근거는 그 사실관계·적용 요건을 검토합니다. 임의의 다른 법령을 억지로 선택할 필요가 없습니다.
4. 법령상 의무·공공기관 소관 업무·다른 법률의 특별한 규정 등 **개별 법령이 필요한 근거를 선택한 때만** 법령 검색이 나타납니다.
5. 법령 검색 결과에서 공식 이름을 선택한 뒤 조·항·호를 선택합니다. 법령을 고르면 검색 목록은 사라집니다. 검색창은 접기 버튼 없이 계속 표시되므로 검색어를 바꿔 다시 찾을 수 있습니다.
6. 조·항·호를 선택하면 이미 받은 원문에서 해당 내용을 즉시 표시합니다. 항을 선택하면 하위 호와 목도 함께 표시합니다. 조문 선택만으로 불필요한 API 재호출을 하지 않습니다.
7. 필요하면 ‘선택한 조문 다시 가져오기’를 사용합니다. 별도의 ‘API로 법령 원문 정보 확인’ 버튼은 없앴습니다.
8. 적용할 항목을 개별 또는 전체 선택하고, 필요한 경우 AI 검토를 받습니다. 적용 이유 입력란은 없으며, 항목명 옆에 미선택 상태 문구도 반복하지 않습니다. 검토 결과와 법령상 요건을 확인하고 적용합니다.

추가 영역의 제목을 누르면 접거나 다시 펼칠 수 있습니다. 내용을 접었다고 바로 적용되거나 입력이 지워지지는 않습니다.

## 포괄 조항과 특별한 근거의 구분

‘법률에 특별한 규정이 있거나 법령상 의무를 준수하기 위하여 불가피한 경우’는 개인정보 보호법 제15조 제1항 제2호의 **연결 근거**입니다. 그 문구 자체만으로 어떤 업무에서 성명·건강정보 등을 처리할 수 있다는 구체적 권한을 확정하지 않습니다.

법령 근거가 필요한 경우에는 해당 업무의 **개별 법률·시행령·시행규칙 조문**까지 선택해야 합니다. 서버는 개인정보 보호법과 그 시행령·시행규칙 자체를 이런 특별한 업무 근거로 다시 채택하는 것을 거부합니다. AI가 포괄 조항만 제안한 경우 적용 법령에서 제외하고 사유를 표시합니다. 특별한 근거를 확인하지 못하면 임의로 지어내지 않습니다.

공식 원문 대조는 조문 존재와 인용 확인입니다. 해당 기관·업무·대상 항목이 법의 적용 요건을 충족한다는 자동 법률 판단은 아닙니다. 사실관계와 최종 적용 여부는 담당자가 확인합니다.

제3자 제공의 제17조 제1항 제2호를 적용할 때는 연결되는 제15조 제1항의 수집 근거도 별도로 조회합니다. 계약 이행을 위해 수집할 수 있다는 이유만으로 계약 근거가 제3자 제공까지 허용한다고 처리하지 않습니다. 목적 외 이용·제공은 제18조의 별도 요건으로 구분합니다.

민감정보·고유식별정보·주민등록번호는 일반적인 수집·제공 근거와 별도의 처리 허용 근거가 함께 필요한 경우를 구분합니다. 허용 조항 하나를 적용한 것만으로 전체 요건이 충족되었다고 표시하지 않습니다. 현재 지원하는 근거는 `law-basis.js`와 `basis-rules.json`에 열거되어 있으며, 모든 예외를 자동 지원하는 것은 아닙니다. 법 개정 시 라벨과 규칙도 검토해야 합니다.

## 검색 범위와 결과 개수

검색 결과는 공식 응답의 법령구분이 **법률·대통령령(시행령)·총리령·부령(시행규칙)**인 자료만 표시합니다. 행정규칙·조례는 표시하지 않습니다. 원본 응답은 20건씩 제한하여 읽되, 필터링 후의 **표시 가능한 결과 5건**을 채웁니다. 남은 원본 위치는 커서로 이어받아 중복·누락 없이 다음 5건을 조회합니다. 한 번에 최대 8개 원본 페이지를 훑고 시간 제한에 도달하면 계속 조회 가능한 커서를 반환합니다. 부분 탐색을 ‘결과 없음’으로 단정하지 않습니다.

검색창은 접기 버튼 없이 계속 표시합니다. 결과 영역은 검색한 후에만 표시합니다. 결과가 5건 이상이면 **다섯 행과 상태 줄을 위한 고정 높이**를 확보하고, 5건 미만이면 실제 행 수만큼 표시합니다. 추가 로딩 중에는 높이를 유지합니다. 로딩 문구는 예약된 상태 줄 안에만 바뀌며 아래 콘텐츠를 밀지 않습니다.

목록 안에서 아래로 스크롤하면 다음 5건을 자동으로 추가합니다. 별도의 ‘다음 5건’ 버튼은 없습니다. 스크롤 위치와 기존 행을 유지하며, 첫 5건이 높이에 딱 맞는 경우에도 끝의 작은 감지 영역과 스크롤 입력으로 추가 조회합니다. 키보드로 목록에 포커스한 후 End 또는 아래 방향키를 사용할 수 있습니다. 조회 실패 시 목록 안의 상태 줄에 재시도 동작을 제공합니다. 결과가 5건 미만이면서 탐색 커서가 남은 경우에는 제한된 횟수 안에서 이어서 조회합니다.

행정규칙 검색 선택지는 제공하지 않습니다. 과거 클라이언트가 includeAdmin을 보내더라도 행정규칙을 조회하지 않으며, 행정규칙 target의 검색·본문 조회·적용 요청은 거부합니다.

## 직접 추가한 법령의 AI 검토

현재 연동한 국가법령정보센터 API는 법령 검색·공식 본문 조회에 사용합니다. 업무와 개인정보 항목별 적용 타당성을 판단하는 기능은 현재 연동 표면에서 확인되지 않아, 별도의 OpenRouter 검토를 추가했습니다. 공식 안내 사이트 접근 제한으로 전체 최신 API 목록을 확인했다고 주장하지 않습니다.

- 직접 추가한 법령에서 사용자가 적용할 항목을 선택한 뒤 필요한 경우 **‘선택 항목 AI 검토’**를 누릅니다. AI 검토는 선택사항이며, 수동 검색과 적용에는 LAW_API_OC만 있으면 됩니다. AI 검색·검토를 실행할 때만 OPENROUTER_API_KEY가 필요합니다.
- 서버가 개별 법령과 개인정보 보호법의 공식 조문을 다시 확인한 후, 선택 항목·처리 목적·제공받는 기관을 함께 AI에 보냅니다. 클라이언트가 쓴 가짜 조문을 근거로 검토하지 않습니다. 필수 사실이 없으면 모델이 임의로 보충하지 않도록 요청합니다.
- 항목별 결과는 **검토상 적용 가능 / 추가 확인 필요 / 적용 권장하지 않음**입니다. 검토 결과가 누락된 항목도 추가 확인 필요로 처리합니다. AI가 실패하거나 불확실하면 성공으로 표시하지 않습니다.
- 추가 확인·반대 의견은 참고사항입니다. **적용 권장하지 않음 의견이 있어도 담당자가 원문·요건을 확인하고 등록할 수 있습니다.** 부정적인 AI 의견을 긍정으로 바꾸거나, 재검토를 강제하지 않습니다. 공식 원문 확인과 담당자의 명시적인 요건 확인·적용 클릭은 유지합니다.
- 검토 결과는 선택한 항목·목적·기관·공식 원문과 연결한 서버 서명으로 보호하고 5분 동안 유효합니다. 항목이나 법령을 변경하면 기존 AI 결과를 초기화합니다. AI 검토를 생략하면 서명 없이 공식 원문을 확인하여 적용합니다. 서명을 제출한 경우에는 만료·변조 여부를 검사하고 거부합니다.
- AI 검토 없이도 담당자 요건 확인 후 적용할 수 있습니다. 적용 시에는 AI를 호출하지 않고 원문과 제출된 서명(있는 경우)을 확인합니다. 검토는 AI 호출 1회가 추가되므로 사용료가 발생할 수 있습니다.

AI 의견은 법률 자문이나 적법성 보증이 아닙니다. 조문 존재 확인, AI의 적용 검토 의견, 담당자 확인을 화면에서 구분합니다.

## 속도와 AI 모델

- 기본 모델은 사용자가 선택했던 `openai/gpt-oss-120b`를 유지합니다.
- AI 생성은 출력 제한·25초 연결/응답 대기를 사용하고, gpt-oss에는 낮은 추론 강도를 적용하며, 가능한 제공자를 지연 시간 기준으로 선택하도록 요청합니다. 공식 API는 개별 요청마다 10초 대기를 적용합니다. 이는 전체 검색 완료 시간을 보장하는 SLA가 아닙니다.
- 개별 업무 법령과 개인정보 보호법의 기본·연결 조항을 병렬로 대조합니다.
- 같은 OC와 같은 법령 요청은 서버 메모리에 **검색 목록 5분·버전(MST)이 지정된 본문 1시간, 최대 64개·원문 합계 32MB** 캐시합니다. 한국 시간 날짜가 바뀌면 새 캐시 키를 사용합니다. 캐시에 OC 원문을 키로 넣지 않으며 파일로 저장하지 않습니다. 다른 OC로 바뀌면 캐시를 공유하지 않습니다. 동시 중복 요청도 합칩니다. 서버 재시작 시 사라집니다.
- 조·항·호 선택은 이미 받은 문서에서 표시하므로 그때마다 AI나 법령 API를 부르지 않습니다. 적용 직전에는 캐시를 우회해 공식 조문을 다시 조회합니다. 같은 적용 요청 안의 중복 조회만 재사용합니다.
- 매우 긴 법령도 조문마다 전체 XML을 반복 검색하지 않고 한 번 순회해 목록을 만듭니다.

응답 속도를 우선 비교하려면 **`openai/gpt-4.1-mini`**를 먼저 시험하는 것을 권합니다. 짧은 구조화 법령 생성에 적합한 비교 법령이며, 현재 환경에서 해당 모델의 속도·가격·가용성을 실측한 것은 아닙니다. `.env`에서 다음 한 줄을 바꾸고 서버를 재시작하면 됩니다.

```dotenv
OPENROUTER_MODEL=openai/gpt-4.1-mini
```

모델의 한국 법률 지식만 믿지 않고 어떤 모델이든 동일한 공식 원문 검증을 거칩니다. `python tests/live_api.py --search`는 OpenRouter 모델 목록에서 ID를 확인한 뒤 실제 검색합니다. 사용료가 발생할 수 있습니다. 더 빠른 모델을 써도 법적 근거의 실제 적용은 담당자가 검토합니다.

## 로컬 설정과 키 보관

Python 3.12 이상을 사용합니다. 별도 Python 패키지는 필요 없습니다. `.env.example`을 복사해 **server.py와 같은 폴더에 정확히 `.env`**로 저장합니다. `key.env`나 `.env.txt`는 자동으로 읽지 않습니다. Windows의 UTF-8 BOM도 지원합니다.

```dotenv
OPENROUTER_API_KEY=본인의_실제_키
OPENROUTER_MODEL=openai/gpt-oss-120b
LAW_API_OC=승인된_OC
HOST=127.0.0.1
PORT=3000
LAW_SEARCH_DEMO=false
```

OpenRouter 키는 <https://openrouter.ai/settings/keys>에서 발급합니다. 법령 OC는 <https://open.law.go.kr/>의 공동활용 신청·승인 안내를 따릅니다. 승인 조건에 따라 서버 IP나 이용 권한을 확인하세요. 실제 값은 채팅이나 GitHub에 올리지 않습니다.

```sh
python server.py
```

브라우저에서 `http://127.0.0.1:3000`을 엽니다. HTML 파일을 직접 열거나 `python -m http.server`를 사용하지 않습니다. 인증정보가 있는 폴더를 일반 정적 서버로 제공하면 파일이 노출될 수 있습니다. 제공한 서버는 허용 목록의 정적 파일만 제공하고 `.env`·`.git`·서버 코드·문서는 제공하지 않습니다.

키는 브라우저·localStorage·HTML에 저장하지 않습니다. Git에는 `.env.example`만 포함합니다. 배포 시에는 백엔드의 비밀 환경변수로 이전하고 `.env`를 이미지나 정적 파일에 넣지 않습니다. 환경변수는 파일보다 우선하며, 비공개 외부 파일은 `APP_ENV_FILE`로 지정할 수 있습니다.

배포에는 Python 백엔드를 실행할 수 있는 플랫폼이 필요합니다. 개발 서버를 그대로 공개하는 대신 운영 HTTP 서버/플랫폼 런타임에 맞게 호스팅하고 HTTPS·사용자 인증·사용자별 비용 한도를 적용합니다. 프록시는 원래 Host를 유지하고 같은 도메인의 `/api/*`를 백엔드로 연결해야 합니다. 기본 분당 6회·동시 2요청 제한은 사용자별 영구 한도를 대신하지 않습니다. 외부 요청의 Authorization 헤더와 법령 API의 OC 쿼리를 로깅하지 마세요.

클라우드에서 실제 API를 쓸 때는 `openrouter.ai`, `www.law.go.kr` 접근이 필요합니다. `open.law.go.kr`은 공식 안내 사이트입니다. 클라우드의 localhost는 사용자의 컴퓨터 주소가 아니며, 링크형 미리보기는 환경에서 HTTP Preview가 제공되어야 합니다.

## 실행 오류와 업데이트

새 ZIP을 받으면 기존 서버를 Ctrl+C로 종료하고, 실제 `.env`를 새 폴더에 복사한 뒤 새 폴더의 server.py를 실행합니다. 브라우저는 Ctrl+F5로 새로고침합니다.

`http://127.0.0.1:3000/api/status`에는 `app: dongui`, **`apiVersion: 8`**이 표시되어야 합니다. aiConfigured/lawConfigured는 값의 존재 여부이며 인증 성공을 보증하지는 않습니다. 키는 출력하지 않습니다.

- 상태 페이지도 안 열림: 로컬 서버 실행·주소·포트를 확인합니다.
- aiConfigured/lawConfigured가 false: `.env`의 경로·정확한 이름·변수명을 확인하고 재시작합니다.
- 외부 API 인증 거부: 키·OC 승인·잔액·사용 한도·허용 도메인을 확인합니다.
- 시간이 초과됨: 처리 항목을 줄이거나 직접 법령 검색을 사용하고, 모델을 비교합니다.

서버 로그는 `API POST /api/law/... 상태코드`만 출력합니다. 요청 본문·키·OC는 로깅하지 않습니다. 오류를 문의할 때는 화면 문구와 상태코드만 공유하세요.

## 테스트

키 없이 서버·정책 검증:

```sh
python -m unittest discover -s tests -p 'test_*.py' -v
node --test tests/basis.test.cjs
```

법령 본문은 합성 XML, 외부 요청은 가상 응답으로 대체하여 검증합니다. 포괄 근거 거부, 항·호·목 계층, 법령 종류 필터, 5건 조회, OC별 캐시 분리, 항목 적용 정책 등을 확인합니다. 이것만으로 실제 외부 API 호출 성공을 주장하지 않습니다.

Playwright·Chromium이 설치된 개발 환경에서 시연 서버를 실행한 뒤 브라우저 검증:

```sh
# macOS/Linux
LAW_SEARCH_DEMO=true PORT=3001 python server.py
# 다른 터미널
TEST_BASE_URL=http://127.0.0.1:3001 node tests/browser.cjs
```

Windows에서는 테스트용 `.env`에 `LAW_SEARCH_DEMO=true`, `PORT=3001`을 넣고 실행할 수 있습니다. 일반 사용자 실사용 서버는 시연 모드를 false로 둡니다. 브라우저 테스트에는 실제 키가 없는 별도 서버를 사용하세요. 테스트의 법령·AI 결과는 브라우저 내부에서 가상 응답으로 대체합니다. 실제 서비스 응답이나 실제 법률 조문으로 오인하면 안 됩니다. 테스트 결과물은 Git에서 제외되는 `.test-output`에 저장합니다.

기본 클라우드 개발 환경에는 Playwright와 Chromium이 있습니다. 일반 로컬에서는 저장소 밖에 설치할 수 있습니다.

```sh
npm install --prefix ../dongui-browser-tools playwright
../dongui-browser-tools/node_modules/.bin/playwright install chromium
```

`NODE_PATH=../dongui-browser-tools/node_modules`와 `CHROMIUM_PATH`를 해당 설치 경로에 맞추세요. Playwright Chromium 경로는 `node -e "console.log(require('playwright').chromium.executablePath())"`로 확인합니다.

실제 인증정보를 이용하는 선택적 테스트:

```sh
python tests/live_api.py
python tests/live_api.py --search
python tests/live_api.py --review
```

첫 번째는 계약 관련 개인정보 보호법 조문·제15조 제1항 전체를 실제 조회하고 AI 검토 없이 적용하는 API 경로를 확인합니다. 두 번째는 AI 법령 검색 1회, 세 번째는 적용 전 AI 검토 1회가 추가되며 과금될 수 있습니다. --review에서 추가 확인 필요가 나오면 검토 응답은 받았지만 적용하지 않은 결과로 구분합니다. 키가 없으면 미실행으로 구분하고 종료 코드 2를 반환합니다. 실제 검색에서 검증된 법령이 0개면 성공으로 간주하지 않습니다.


## 전체 건수 집계

첫 5건을 먼저 표시한 후 `/api/law/count`가 법률·시행령·시행규칙 필터와 시행일 조건을 동일하게 적용하여 별도로 집계합니다. 원본 100건씩 최대 20회 조회하며 집계 완료 시 전체 건수를 표시합니다. 범위가 너무 넓거나 응답 오류가 나면 `전체 건수 확인 불가`로 표시하며, 일부 건수를 전체 건수로 오인시키지 않습니다. 검색 결과의 추가 로딩은 계속 사용할 수 있습니다. 집계는 AI를 호출하지 않습니다.

원문 보기는 선택한 호만이 아닌 해당 항 전체를 표시합니다. 제15조 제1항 근거를 선택하면 제1항의 하위 호·목도 함께 표시합니다. 정당한 이익 근거에는 개인정보처리자의 입증 책임 경고를 표시합니다. 모델명·서비스명·검토 시각은 화면에 표시하지 않으며 운영 설정은 서버 문서와 `/api/status`에서 확인합니다.


## 검색된 개인정보 보호법 근거 표시

AI 검색 결과의 제목은 `개인정보 보호법 제15조 제1항 제4호`처럼 조·항·호로 표시합니다. 제목 아래에서 같은 인용이나 근거 이름을 반복하지 않고 바로 ‘전문 보기’를 제공합니다. 항이 지정된 검색 결과는 해당 항 전체와 하위 호·목을 표시하고, 선택한 호를 굵은 글씨와 연한 배경으로 강조합니다. 강조는 공식 원문의 호 번호를 기준으로 하며 다른 호에 같은 문구가 있어도 구분합니다. 직접 추가 화면의 원문 보기는 기존처럼 선택한 항 전체를 표시합니다. ‘이 유형에서 검토할 개인정보 보호법 조항’ 안내 영역은 제거했습니다.

직접 선택의 조·항·호는 한 줄에 표시합니다. 조 목록에서는 제목을 함께 보여주고, 선택 후에는 `제15조`처럼 짧게 표시합니다. 항·호가 없으면 `항 없음`·`호 없음`으로 회색 비활성화합니다. ‘전체선택’과 개별 항목의 체크박스 위치를 맞췄습니다.

공통 적용 요건 확인 체크박스는 AI가 찾은 근거를 적용할 때 표시합니다. 직접 등록에서는 이 공통 체크박스 없이 적용할 수 있습니다. 개별 법률·시행령·시행규칙의 구체적인 처리 권한 확인과 주민등록번호의 별도 허용 요건 확인은 필요한 경우 유지합니다.

AI 법령 후보에는 검색 1회당 별도의 개수 제한을 두지 않습니다. 직접 검색 목록의 5건 단위 표시는 스크롤 로딩 단위일 뿐 총 결과 수 제한이 아닙니다. 후보 없음·공식 검증 탈락·조회 실패·일부 확인·모두 확인을 구분하며, 후보가 없다는 이유로 동의 없는 처리 근거가 없거나 동의만 받으면 된다고 판단하지 않습니다.

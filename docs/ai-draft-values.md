# 수정 가능한 AI 초안

업무 대화에서 원문으로 확정하지 못한 항목·보유기간도 AI가 최소 초안으로 제안한다. 공식 원문으로 확인한 `items`·`period`와 별도로 `suggestedItems`·`suggestedPeriod`·`suggestionReason`을 반환하며, 제안값은 검증된 사실의 서명에 포함하지 않는다. 제안값만으로 법적 근거를 승인하지 않는다. 진료의 제안 항목은 실제 원문과 항목별 적용 검토를 따로 통과한 근거에 한해 연결한다.

화면은 확인된 값이 없는 부분에 제안값을 채우고 ‘AI 초안 · 확인 필요’로 표시한다. 사용자가 항목과 기간을 바로 수정한 뒤 문서 작성 단계로 이동할 수 있다. 원문으로 확인된 기간이 있으면 초안 기간으로 덮어쓰지 않는다. 기관명·제공받는 기관명은 추측하지 않으며, 주민등록번호를 추정 초안으로 추가하지 않는다. 기존 별도 처리 근거 검증은 유지한다.

챗봇 상단에는 ‘AI는 틀릴 수 있습니다. 자동 입력된 항목·보유기간·법적 근거를 확인하고 수정해 주세요.’ 안내를 항상 표시한다. 4단계의 보조 입력란은 미입력 값만 제공하고, 이미 입력된 항목·목적·기간은 앞 단계에서 수정한다. 이 안내는 대화·편집 UI에 표시하며 동의서 원문에 AI 문구를 추가하지 않는다.

검증: Worker 97건·Python 84건, 초안 입력·수정·문서 전달 브라우저 시험, 기존 업무 대화 브라우저 시험, Cloudflare 배포 빌드 검사를 통과했다. 실제 AI 모델의 제안값은 업무 설명과 확인된 자료에 따라 달라진다.


## 진료 판단과 편집 화면 개선

의료법 시행령 제42조의2 원문에서 건강정보·주민등록번호 처리와 제3호의6의 진료기록부등 기록 사무를 확인했다. 진료 목적과 그에 수반되는 진료기록 작성을 함께 검토하되, 단순 예약·홍보·익명 상담과 구별한다. 사용자가 ‘불가피’라는 단어를 반복하지 않았다는 이유로 사실 부족을 판단하지 않도록 검토 지침을 보완했다. 실제 주체·업무·항목의 요건 검토는 유지한다.

동일 원문이 주민등록번호와 민감정보 처리를 허용하면 두 허용 근거를 각각 확인한다. 진단명 등 초안 건강정보도 실제 원문과 적용 가능성을 검토하고, 일반 근거와 민감정보 근거가 모두 유효할 때 고지사항으로 분류한다. 원문 확인 없이 모든 진료 항목을 고지사항으로 바꾸지는 않는다.

챗봇은 기관 고유 명칭을 질문하지 않는다. 기관명은 4단계에서 입력하며 미입력 서식에는 ‘기관명’을 표시한다. 법 적용에 필요한 기관 유형 확인은 유지한다. 같은 분류의 질문은 하나의 제목 아래 묶는다. 오른쪽 개인정보 항목은 개수만 보이고 펼치면 목록을 볼 수 있다. 초안 수정 칸도 접어 둔다.

4단계는 기관명·문서 제목·안내사항을 각각 별도 상자에 표시한다. 기본 후보는 자동 적용하므로 후보 적용 버튼은 제거했다. 빈 항목·목적·기간·제공받는 기관만 보조 입력란을 제공한다. 기존 값은 1~3단계에서 수정한다.

화면·회귀 검증: Worker 98건·Python 85건, 진료 민감정보의 고지사항 분류, 기관명 질문 제거, 질문 분류 통합, 접힌 항목 목록, 4단계 빈 값 전용 입력, 기관명 서식 기본값, 개별 설정 상자, 기존 대화·초안·복구, 미리보기/PDF/HWPX와 전체 브라우저 수용 검사를 통과했다. 빠른 생성의 기본 제목은 문서 유형에 맞춰 자동 갱신하고 직접 수정한 제목은 유지한다.

운영 AI 진료 시험은 약 259초에 HTTP 200을 반환했으나 의료법 시행령 제42조의2의 재조회가 실패하여 주민등록번호 허용을 실제로 확정하지 못했다. 이를 ‘불가피성 미충족’으로 단정하지 않고 원문 조회 실패로 남겼다. 이후 같은 요청에서 이미 내려받은 동일 MST 공식 전문을 조문 검증에 재사용하도록 Worker와 Python을 보완했다. 해당 조문이 전문에 없으면 기존 개별 조회·MCP 대체를 수행한다. 재사용 회귀 검사를 포함한 Worker 99건·Python 85건을 통과했다. 이 보완 후 실제 AI 재시험의 성공까지 확인했다는 의미는 아니다.

## 업무 의무·계좌 항목·지출증빙 보존을 함께 검토

최초 검색 입력에 업무 의무/특수정보 허용, 실제 필요 항목/공식 서식, 회계·기록물 보존기간의 세 범위를 명시한다. 국가기록원·행정안전부·기획재정부 공식 도메인을 포함하고 세법에만 치우치지 않도록 한다. 공식 검색 보고서와 제한된 출처 발췌를 초안 작성 단계에도 전달한다. 보존 관련 법령은 업무 핵심 법령 다음에 우선 조회하며, 지침·기준표를 법률인 것처럼 등록하지 않는다.

일반 개인정보는 법정 원천징수·지급명세서 제출·진료기록 작성 업무에 필요한지 판단한다. 조문에 항목명이 없거나 독립적인 수집 허용 문장이 없다는 사유만으로 배제하지 않도록 검토 지침을 보완했다. 필요한 일반 항목의 초안도 공식 원문과 항목별 적용 검토를 수행한다. 주민등록번호·민감정보의 별도 허용 요건과 원문 존재 검사는 유지한다.

강사료·강연료·자문료에는 성명·은행명·계좌번호·예금주명을 수정 가능한 초안으로 보완한다. 사용자의 명시적 제외를 우선한다. 공공기관 지급 업무의 기간이 빈 값 또는 ‘확인 필요’이면 5년을 초안으로 입력한다. 이 값은 법정 기간으로 승인한 것이 아니며, 지출증빙의 대상 서류·기관 기준·기산점을 확인하도록 표시한다. 확인된 기간은 초안으로 덮어쓰지 않는다.

질문은 서버에서 분류별 하나로 합친다. 항목·기간을 중복해 묻지 않으며, 화면에서도 같은 분류의 복수 질문을 한 번에 표시한다. 사용자에게 법령·조문을 찾아오라고 요청하는 질문은 제외한다. 기관 고유 명칭은 계속 4단계에서 입력한다.

검증: Worker 103건·Python 87건, 지급 계좌 기본값·제외 지시·5년 초안과 확정 기간의 분리·필요 항목의 적용 검토·보존 법령 우선 조회·초기 검색 세 범위 구성·질문 통합, 진료/초안/기존 대화 화면 검사를 통과했다.

운영 강사료 시험은 약 86초에 HTTP 200으로 완료됐다. 성명·은행명·계좌번호·예금주명과 5년 초안을 반환했고, 필요 일반 항목은 확인된 업무 근거에 대해 항목별 적용 검토를 받았다. 5년을 공식 보존기간으로 확정한 시험은 아니며 해당 표시는 계속 초안이다. 계좌이체 여부 재질문은 항목 수정 질문에 합치고, 법령상 허용 근거를 사용자가 확인했는지 묻는 대신 실제 사용 업무·용도를 확인하도록 추가 정규화했다. 마지막 회귀 검사를 포함해 Worker 104건·Python 87건을 통과했다.

## 추가 답변에 따른 재검색과 주민등록번호 요청 보관

새 사용자 메시지가 들어오면 기존 확인 근거가 있어도 최초 검색부터 다시 수행한다. 원래 업무와 최근 답변을 함께 검색하고, 최근 사용자 답변 전문도 조사 입력에 제공한다. 체크포인트는 원래 업무에 계속 연결하며, 기존 확인 사실·참고 조문은 유지한다. 새 사용자 입력이 없는 단순 재검증과 새로고침은 자동으로 유료 검색을 시작하지 않는다.

소득세법 계열뿐 아니라 국세기본법 시행령도 원천징수 업무의 별도 식별번호 근거 탐색에 포함한다. 원문 대조에서 제68조제3항의 원천징수의무자 규정이 제1항의 개인정보 범위를 참조함을 확인했다. 앞항의 세무공무원 주체를 후항의 별도 주체에 그대로 추가하지 않도록 판단 지침을 보완했다. 실제 업무·주체·항목 적용 검토는 유지하고, 일반 근거 검토에도 확인된 별도 허용 근거를 함께 제공한다.

사용자가 명시적으로 주민번호 수집을 요청하면 주민등록번호로 정규화하여 요청을 보관한다. 일반 근거와 별도 허용 근거를 모두 검토한 후에만 문서 항목으로 전달하며, 미확인 요청은 삭제하지 않고 재확인 항목으로 보관한다. 다시 근거가 없는지 묻는 경우 새 검색 후 확인 상태를 설명하고, 이전 미해결 질문 목록을 반복하지 않는다. 이미 답한 기타소득 구분·주민등록번호 사용 여부도 다시 묻지 않는다.

집계는 확인값·초안·재확인 항목을 합친 총개수와 각각의 개수로 안내한다. 화면의 ‘없어요 · 문서 작성으로’ 버튼은 DOM과 시각 순서 모두 마지막·오른쪽에 배치한다.

검증: Worker 107건·Python 88건, 추가 답변 재검색·약칭 인식·주민등록번호의 일반/별도 근거 동시 검토·요청 보관·총개수 집계·반복 질문 방지, 대화/복구/진료 화면 검사를 통과했다.


추가 검증에서 첫 답변은 약 86초에 총 5개 항목과 국세기본법 시행령 제68조제3항의 허용 근거를 확인했다. 재질문 시험은 새 검색을 수행했지만 부가 조회에 예산이 소진되어 핵심 근거를 다시 확인하지 못했다. 이 결과에 따라 선택적 탐색의 한도를 실제로 제한하고 주민등록번호의 허용 근거와 일반 근거를 먼저 검증하도록 보완했다. 조회 실패를 근거 부재로 설명하지 않으며, 재질문에는 미해결 질문 목록을 반복하지 않는다.

확인된 소득 구분과 명백히 다른 조문 제목(예: 기타소득 업무의 사업소득 전용 조문), 가산세·과태료·벌칙 조문은 자동 적용 근거에서 제외한다. API와 MCP 모두 공식 조문 제목을 판단에 사용한다. 보관 중인 미확인 주민등록번호 요청도 체크포인트와 같은 형식으로 정규화하여 후속 답변에서 서명 오류 없이 이어가도록 검증했다. 수집 불필요 의사는 신규 수집 요청으로 해석하지 않는다. 최종 자동 검증은 Worker 112건·Python 89건을 통과했다.

보완 후 운영 재질문 시험: 이전의 확인된 체크포인트를 사용해 ‘정말 주민번호 수집 근거가 없는 건가요?’를 전송했다. 약 66초에 HTTP 200으로 완료됐고, 새 검색 후 국세기본법 시행령 제68조제3항을 다시 확인했다. 일반 처리 근거와 별도 허용 근거가 함께 적용 검토됐으며, 총 5개 항목(입력·원문 확인 1개·초안 4개), 재확인 0개, 추가 질문 0개를 반환했다. 조건 확인 사항은 번호를 원천징수·지급명세서 업무의 필요한 범위에 사용하는지 등으로 유지했다.

2026-11-26 추가 개선: 오른쪽 요약에 일반 수집·이용 근거와 주민등록번호·민감정보 등의 별도 허용 근거를 구분하여 법률명·조항을 항상 표시한다. 항목별 상세는 접어서 유지하며, 근거 미확인 항목은 개수와 명시적 미확인 안내를 표시한다. 챗봇 답변도 일반 근거와 주민등록번호 허용 근거를 함께 설명한다. 이미 알려준 강사료·주민등록번호 사용 용도를 포괄적으로 다시 묻지 않고, 확정한 기간·항목 질문도 반복하지 않는다.

O/X 질문에는 해당 질문 전용 버튼을 표시한다. 기간 유지·현재 항목 유지는 실제 현재 값을 포함하여 답변하고 새 검색을 수행한다. 기간 변경·항목 변경은 수정 입력칸으로 연결하며, 미완성 답변을 자동 전송하지 않는다. 다른 질문에 대한 동의로 해석하지 않는다. 검증은 Worker 114건·Python 90건, 기존 진료/챗봇 화면 검사, 신규 법률 표시·미확인 표시·O/X 답변·모바일 검사 및 Cloudflare 배포 사전 검사를 통과했다. 신규 화면 검사는 모의 API 응답으로 검증했다.

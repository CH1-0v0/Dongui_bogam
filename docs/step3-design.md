# 3단계 디자인 다듬기

브랜치: `feature/step3-review-polish`. 기존의 파란색·회색 팔레트와 글꼴을 보존하고, 문서 작성 도구의 읽기 순서와 상태 구분을 다듬었습니다. 이미지에는 합성 테스트 데이터가 쓰였으며 실제 법령이나 외부 API 검토 성공의 증거가 아닙니다.

## 기존 문제와 변경 방향

- 제목·본문·보조 설명의 시각적 무게가 비슷했습니다. 유형 제목, 작업 단계, 본문, 메타데이터를 별도 역할로 구분했습니다.
- 작은 박스가 반복되어 단계보다 테두리가 먼저 보였습니다. 단계 내부의 배경·테두리를 줄이고 여백과 굵은 제목으로 의미를 묶었습니다.
- 적용·보류 후보를 목록에서 숨겨 다시 검토하기 어려웠습니다. 후보를 삭제하지 않고 상태를 표시한 접힌 항목으로 보존합니다.
- 다음 결과를 받는 동안 목록과 아래 화면이 흔들릴 수 있었습니다. 다섯 행과 상태 줄을 고정 높이로 확보하고 기존 DOM 행·스크롤 위치를 유지합니다.

## 검증한 역할과 대비

| 역할 | 데스크톱 실제 렌더링 | 의도 |
| --- | --- | --- |
| 개인정보 유형 제목 | 24px / 800 / 32.4px 행간 | 대분류의 시작 |
| 작업 단계 제목 | 20px / 800 / 28px 행간 | 다음 행동 안내 |
| 본문·작업 설명 | 16px / 400 / 28.8px 행간 | 실제 읽는 내용 |
| 목적·메타데이터 | 13px / 400 / 22.1px 행간 | 보조 맥락 |

단계 사이에는 32px 간격을 두고, 제목과 관련 설명은 가깝게 배치합니다. 팔레트를 변경하지 않은 상태에서 계산한 대비는 본문/흰색 14.97:1, 보조 글자/연한 배경 5.77:1, 주 버튼 6.65:1, 경고 글자/경고 배경 6.41:1입니다. 이 값이 전체 앱의 모든 색 조합을 자동으로 보증한다는 의미는 아닙니다.

## 검색과 검토 상태

- 데스크톱 검색창은 88px 행 5개·44px 상태 줄·테두리로 486px 높이입니다. 모바일은 96px 행 5개로 526px이며 두 화면에서 실제 다섯 행이 보이는지 검사했습니다.
- 첫 조회, 추가 로딩, 오류, 종료 상태를 같은 공간 안에서 표시합니다. 지연 응답 테스트에서 목록 높이와 아래 콘텐츠의 문서상 위치가 로딩 전·중·후 동일했습니다.
- 목록은 키보드로 포커스할 수 있고 끝에서 스크롤하면 이어서 조회합니다. 오류 후에는 상태 줄의 재시도로 복구하며 자동 반복 요청을 하지 않습니다.
- 선택 항목명 옆에 미선택 상태 문구를 반복하지 않습니다. 선택 여부는 체크박스로 나타냅니다.
- AI 검토 결과는 검토상 적용 가능, 추가 확인 필요, 적용 권장하지 않음으로 구분합니다. 검토 오류와 누락을 성공으로 표시하지 않습니다. 항목·법령 변경 시 재검토가 필요합니다.

1440px, 768px, 390px 화면과 200% 확대에서 가로 넘침을 확인했습니다. 후보 접기·복원·재검색 보존, 입력 영역 접기, 항·호·목 표시, AI 검토 및 적용, PDF·HWPX 출력을 브라우저에서 검증했습니다. 외부 API 호출은 가상 응답으로 대체했으므로 실제 모델의 정확도·속도·가용성은 별도 검증이 필요합니다.

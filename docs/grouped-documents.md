# 같은 개인정보 구분의 표와 공통 내용 통합

4단계 미리보기·쪽 미리보기·최종본·PDF·HWPX에서 같은 처리 유형과 개인정보 구분을 한 표에 표시합니다. 일반 개인정보(필수)·일반 개인정보(선택)·민감정보·고유식별정보 등의 구분을 유지합니다.

- 같은 구분의 동의 대상과 고지 대상도 한 표로 묶습니다. 둘이 함께 있으면 ‘처리 방식’ 열에 **동의 / 고지**를 표시합니다. 동의 체크 문구에는 동의를 받는 항목명만 표시하고 고지 항목에 동의를 요구하지 않습니다.
- 고지 항목의 목적·보유기간·제공받는 자·처리 근거가 모두 같으면 항목명을 한 행에 모읍니다. 근거가 다르면 다른 행으로 유지합니다.
- 연속한 행의 같은 목적·보유기간·제공받는 자·근거는 셀을 병합합니다. 목적이나 보유기간을 직접 수정하면 병합된 셀에 해당하는 모든 행에 함께 반영됩니다.
- 다른 처리 유형이나 서로 다른 내용은 무리하게 합치지 않습니다. 별도 고지 대상만 있는 구분도 같은 병합 방식을 사용합니다.

## 검증

서버 테스트·근거 규칙 테스트에 더해 Playwright와 Chromium이 설치된 환경에서 시연 허용 서버를 실행하고:

```sh
TEST_BASE_URL=http://127.0.0.1:3008 node tests/browser.cjs
TEST_BASE_URL=http://127.0.0.1:3008 node tests/classification-browser.cjs
TEST_BASE_URL=http://127.0.0.1:3008 node tests/document-groups.cjs
```

브라우저 검증은 합성 API 응답을 사용합니다. 항 전체·선택 호 강조, 모바일 한 줄 선택 칸, 항·호 없음 표시, 전체선택 정렬, AI 근거 적용의 확인란과 직접 등록의 공통 확인란 생략, 짧은 민감정보 가능성 표시를 확인합니다.

문서 테스트는 같은 구분의 동의·고지 표 통합, 고지 항목 묶음, 서로 다른 법률 근거의 행 보존, 공통 목적·보유기간의 3행 병합과 편집 내용 유지를 검사합니다. PDF는 여러 행의 병합 및 페이지가 나뉘는 긴 셀을 처리하도록 수정했습니다. 생성한 PDF의 텍스트와 HWPX XML에서 공통 목적의 중복·누락 여부와 병합 속성을 추가 확인했습니다.

실제 API 인증·모델 판단 정확도는 이 환경에서 검증하지 못했습니다. 기존 `.env`를 새 폴더의 `server.py` 옆에 두고 서버를 재시작한 뒤 Ctrl+F5로 새로고침하세요. `/api/status`의 `apiVersion`은 **7**입니다.


한글(HWPX)의 동의·미동의 줄은 테두리 없는 1행 2열 표로 생성합니다. 설명은 왼쪽 정렬, 선택란은 오른쪽 정렬이며 원래 안내 문구와 동의 대상 범위를 유지합니다. 기관 귀중 문구는 웹·PDF·HWPX에서 크게 표시합니다. 고지사항만 있는 경우 동의 거부 입력란은 해당사항 없음으로 표시하고, 고지사항 전용 안내문 후보를 제공합니다.

생성한 파일의 병합·테두리·정렬·글자 크기와 PDF 텍스트의 중복·누락은 `python tests/check_exports.py`로 다시 확인할 수 있습니다. PDF 텍스트 검증에는 `pdftotext`가 필요합니다.

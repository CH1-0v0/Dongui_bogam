# 입력·분류·법령·문서 화면 정리

## 1단계

항목 선택창은 최대 180px 높이 안에서 스크롤합니다. 화면 아래쪽에서는 위로 열어 선택창이 화면을 벗어나지 않게 합니다. 직접 입력을 선택하면 선택 칸을 왼쪽에, 텍스트 입력 칸을 오른쪽에 배치합니다. 선택 칸의 너비를 넓히고 일반·민감·고유식별정보 분류의 색상과 굵기를 구분했습니다. 분류 표시는 입력 칸의 시작보다 조금 안쪽에 표시합니다.

항목 앞 손잡이를 드래그해 순서를 바꿀 수 있습니다. 필수 항목이 먼저, 선택 항목이 나중에 표시됩니다. 필수 여부를 바꾸면 필수의 마지막·선택의 첫 번째가 만나는 경계로 이동합니다. 드래그로 순서를 바꿔도 필수·선택 순서를 유지합니다. 손잡이에 키보드 포커스를 두고 위·아래 화살표로 이동할 수도 있습니다.

직접 입력한 항목만 추가 API 분류 대상으로 삼습니다. 결과는 최대 `민감정보 가능성 높음(건강 사항 포함)`처럼 짧게 표시합니다. 원래 선택 목록의 알려진 항목은 로컬 유형 분류를 사용합니다. [분류 API 설정](privacy-classification.md)을 참고하세요.

## 2단계

개인정보·목적 외 이용·제3자 제공·마케팅을 탭 없이 한 화면에서 확인합니다. 각 처리 유형 안에 일반 개인정보(필수)·일반 개인정보(선택)·민감정보·고유식별정보 영역을 표시합니다. 항목 아래 분류 문구와 필수/선택 스위치를 반복하지 않습니다.

손잡이를 끌어 같은 처리 유형 안에서 분류를 바꿉니다. 다른 처리 유형으로의 이동은 허용하지 않습니다. 키보드로는 손잡이에 포커스를 두고 좌우 화살표로 분류를 바꾸고, 위아래 화살표로 같은 분류 안의 순서를 바꿀 수 있습니다. 터치 기기에서는 손잡이를 누른 채 이동합니다.

## 3단계

직접 등록은 일반 수집 / 목적 내 제공 / 목적 외 이용·제공을 먼저 선택한 뒤 적용할 개인정보를 고릅니다. 동일한 업무 법령을 여러 개인정보 유형에 한 번에 적용할 수 있습니다. 민감정보·고유식별정보·주민등록번호는 별도 법정 요건을 추가 확인하며 주민등록번호는 동의로 대체할 수 없습니다. 적용 법령 수정 버튼은 접힌 내용 밖에 표시합니다.

법령 자동 검색 결과는 선택한 항 전체와 하위 호·목을 표시하고 선택한 호를 강조합니다. 공식 원문의 호 번호를 사용하므로 같은 문구가 다른 호에 있어도 구분합니다. 조·항·호 칸은 모바일에서도 한 줄로 표시하며, 선택한 조는 짧은 번호로 표시하고 목록 안에서는 조 제목을 보여줍니다. 없는 항·호는 회색 비활성화합니다.

‘전체선택’과 항목 체크박스를 같은 위치에 맞췄습니다. 공통 요건 확인란은 AI가 찾은 근거에 표시하고 직접 등록에서는 생략합니다. 구체적인 법령상 처리 권한과 주민등록번호의 특별 요건 확인은 필요한 경우 유지합니다.

## 4단계와 저장

동의 항목은 구분별 별도 동의란을 유지하고, 고지사항은 날짜·서명 바로 앞에 분리합니다. 고지사항은 실제 법령 근거와 처리 조건이 같으면 개인정보 유형이 달라도 한 행으로 묶습니다. [표 통합 안내](grouped-documents.md)를 참고하세요.

문서 수정 요청 기능은 제거했습니다. 완성 버튼은 미리보기 위·아래에 표시합니다. 고지사항만 있으면 동의 거부 입력란 대신 `동의를 받아 개인정보를 수집하지 않기 때문에 해당사항 없습니다.`를 회색으로 표시합니다. 안내문 후보도 별도의 동의를 받지 않는 고지사항에 맞게 제공합니다.

기관 귀중 문구를 크게 표시합니다. 한글(HWPX) 동의·미동의 줄은 테두리 없는 2열 표로 만들며 왼쪽 설명은 왼쪽, 선택란은 오른쪽 정렬합니다.

## 실행·검증

기존 `.env`를 새 폴더의 `server.py` 옆으로 복사하고 서버를 재시작한 다음 Ctrl+F5로 새로고침하세요. `/api/status`의 `apiVersion`은 **8**입니다.

서버 테스트와 근거 규칙 테스트, Playwright의 법령 흐름·민감정보 분류·문서 통합·화면 조작 검증을 수행합니다. 별도 화면 조작 검증은 다음 명령으로 실행합니다.

```sh
TEST_BASE_URL=http://127.0.0.1:3008 node tests/workflow-layout.cjs
```

브라우저 API 응답은 합성 데이터입니다. 실제 API 인증·판단 정확도를 입증하지 않습니다. 한글 저장은 XML 구조에서 테두리 없음·좌우 정렬·글자 크기를 확인했으며 실제 한글 프로그램의 렌더링을 이 환경에서 확인한 것은 아닙니다.

화면 조작 검증은 마우스 드래그, 키보드 이동 및 터치 입력을 검사합니다. 파일 내보내기 검증 후 `python tests/check_exports.py`를 실행하면 한글 표 구조와 PDF 텍스트 중복·누락을 확인할 수 있습니다.

## 최종 화면 보완

- 모두 필수·모두 선택은 항목 오른쪽 위에 배치하고 첫 항목 위 구분선을 제거했습니다. 목록은 자주 쓰는 순서로 표시하며 유형별 구분 배경을 통일했습니다. 필수·선택 변경으로 항목이 이동하면 320ms 애니메이션을 적용합니다. 움직임 줄이기 설정에서는 생략합니다.
- 마케팅은 선택사항으로 고정하며 필수 영역을 비활성화합니다. 고유식별정보는 같은 분류 안에서 순서만 바꿀 수 있습니다. 마우스·터치·키보드와 분류 변경 처리에서 동일한 제한을 적용합니다.
- 개인정보 보호법 근거의 원문 보기는 해당 항 전체를 표시하고 선택한 호를 강조합니다. 검색·선택 중 빈 결과창을 5행 높이로 늘리지 않습니다. 적용 취소 버튼은 붉은색으로 구분합니다.
- 일반 개인정보 필수·선택을 한 표로 묶습니다. 목적 외 이용, 목적 외 제공, 제3자 제공, 홍보 또는 마케팅 관련은 각각 처리 유형 단위의 표와 동의란을 사용하며 특별한 개인정보 항목만 강조합니다. 고지 표의 보유기간도 강조합니다.
- 기본 화면에 실제 A4 페이지·전체 쪽수·쪽 번호를 표시합니다. 별도 쪽 미리보기 버튼은 제거했습니다. 표 편집을 저장하면 페이지를 다시 그립니다.
- 최종 점검의 담당자 확인 사항을 먼저 보여주고, 필수 고지 항목 기재와 동의란 구분의 상세 체크 목록은 각각 +/−로 펼쳐 확인합니다.

새 검증: `TEST_BASE_URL=http://127.0.0.1:3015 node tests/final-layout.cjs` 후 `python tests/check_final_layout.py`로 처리 유형별 동의란, A4 여러 쪽, 한글 표 줄 간격을 확인합니다. 법령 응답은 합성 데이터이며 실제 한글 프로그램의 렌더링을 확인한 것은 아닙니다.

## 과다 수집 경고와 쪽 이동

전체 단계의 검토 현황에 개인정보 항목 수를 오른쪽으로 표시합니다. 입력된 목적과 항목명을 사용한 간단한 로컬 점검으로 회원가입·이벤트·선물 증정 등의 목적에 주민등록번호·고유식별정보·민감정보가 포함되는 경우를 경고합니다. 처리 유형별로 가능성이 있음/적음만 간단히 표시하고 목적이 비어 있으면 입력을 안내합니다. 경고는 다음 단계 이동이나 적용을 차단하지 않습니다. 법령상 주민등록번호 처리 허용 근거를 요구하는 기존 기능과는 별개입니다. 점검은 모든 업무의 필요성을 판단하는 기능이 아니며 최종 판단은 담당자가 합니다.

A4 미리보기는 한 쪽씩 표시하고 화면 높이에 맞춰 한 페이지를 전체 표시합니다. 이전 쪽·다음 쪽으로 이동하며 전체 쪽의 캔버스는 재사용합니다. 문서의 고지사항은 날짜와 서명 직전에 배치하고 PDF·한글에도 같은 순서를 적용합니다.

담당자 확인 항목의 중복 배지는 제거했습니다. 필수 고지 항목 기재·동의란 구분의 설명은 접혀 있어도 보이며 제목 뒤 +/−를 누르면 상세 체크리스트가 열립니다. 해당사항 없는 점검은 회색으로 최하단에 모읍니다.

검증: `TEST_BASE_URL=http://127.0.0.1:3016 node tests/collection-review.cjs`는 모든 단계에서 경고가 진행을 차단하지 않는지, 쪽 이동과 페이지 높이, 설명과 접기 표시, 최하단 제외 항목을 확인합니다.

## 미리보기 크기와 최종 작업

검토 현황은 1~3단계에서만 표시합니다. 최종 점검의 담당자 확인 목록에는 과다 수집 가능성을 별도 항목으로 포함합니다. 미리보기는 스크롤 위치·화면 높이에 따라 축소하지 않고 처음부터 가로 폭에 맞춥니다. 위·아래에 이전/다음 쪽 버튼을 표시하고 상단에 축소·확대·가로 맞춤을 제공합니다. 기본 100%에서는 가로 스크롤이 없으며 수동 확대 시에만 미리보기 내부 스크롤을 허용합니다.

상단 완성하기는 내용 직접 수정하기 오른쪽에 두고 화살표를 생략합니다. 하단 완성하기 →는 유지합니다. 최종본에서 새 동의서 만들기를 누르면 문서·법령 선택·편집 상태를 초기화해 1단계부터 새로 작성합니다.

한글 표의 구분 열을 좁히고 위·아래 내부 여백을 각각 4.2pt로 늘렸습니다. 단어 단위 줄바꿈을 우선 적용합니다. 거부 안내의 '거부할 경우' 뒤 쉼표를 제거했고, 날짜 아래에는 빈 문단 하나, 기관 귀중 앞에는 기존보다 빈 문단 하나를 추가합니다. 인쇄·PDF 제목에는 네 면 테두리를 표시합니다. 최종 점검의 문단·목록 간격을 줄였습니다.

항목 목록과 용역·유지보수 기본 양식의 소속 표기를 소속 기관명으로 통일했습니다. 소속 업체명·소속 회사명·소속 기업명 입력도 새 표기로 정리합니다.

메인 화면의 동의서 생성은 작성 내용이 있으면 삭제 후 새로 시작할지 확인합니다. 취소하면 내용을 보존하며 상단 문서 작성으로 돌아갈 수 있습니다. 확인하면 항목·기관·목적·법령·편집 상태를 초기화해 1단계에서 시작합니다. 빈 문서는 확인 없이 시작합니다.

3단계 검토할 법령의 개별 제목은 파란 배경 띠로 구분하고 펼친 본문은 흰색으로 표시합니다. 처리 근거·조문 제목·전문 보기·적용 항목 소제목에 서로 구분되는 배경·굵기·여백을 적용했습니다.

## 미리보기와 검토 표시 보완

기본 드롭박스 항목은 분류 확인 목록에서 제외하며 직접 입력 항목은 `항목명 → 분류`로 표시합니다. AI 응답 본문이 끊기면 불완전한 내용을 폐기하고 전체 35초·최대 2회 범위에서 재시도합니다. 법령명·조문이 빠진 제안은 AI 정보 누락으로 설명합니다.

미리보기는 PDF 준비 중에도 문서 내용을 먼저 보여주고 첫 쪽부터 표시합니다. 3단계에서 정적 PDF 자원을 미리 준비하며 같은 문서의 렌더링 결과를 메모리에서 재사용합니다. 기본 배율은 가로 맞춤이고 확대 시 가로 스크롤을 허용합니다. 직접 수정 모드의 편집 가능 셀은 색과 점선으로 표시됩니다. 최종 담당자 확인 영역은 접을 수 있고 직접 체크할 수 있습니다. 이 체크는 법률 적합성의 자동 승인을 의미하지 않습니다.

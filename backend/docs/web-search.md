# OpenRouter 웹 검색으로 법령 근거 찾기

추가 패키지 설치나 Exa 키 없이 기존 OPENROUTER_API_KEY를 사용합니다. 법령 원문 조회에는 기존 LAW_API_OC가 필요합니다. 이번 통합은 최신 main의 법령 캐시·시행규칙 종류 인식·검색 상태 안내를 유지합니다. 직접 법령 등록의 본문 키워드 검색은 제공하지 않습니다.

## 처리 순서

1. 항목명·처리 목적·정보 유형을 Responses API `/api/v1/responses`에 전달합니다.
2. `tools`에 `openrouter:web_search`를 등록합니다. Exa 엔진으로 법령정보센터·국세청·보건복지부·개인정보보호위원회 등의 공식 사이트를 검색하도록 요청합니다.
3. 응답의 실제 `url_citation` 주석에서 허용된 공식 도메인 출처를 수집합니다. 검색 보고서와 출처가 없거나 응답이 미완료이면 후보 생성을 중단합니다. 기억 기반 검색으로 자동 대체하지 않습니다.
4. 강사료·자문료/기타소득 및 진료 업무는 법령군과 업무 검색어를 사용하고, 다른 업무는 검색 자료에서 AI가 법령명을 고릅니다. 조문 번호는 이 단계에서 생성하지 않습니다.
5. 국가법령정보센터에서 해당 현행 법령 전문을 조회합니다. 제목·본문의 업무 용어와 별도 허용 용어로 법령별 상위 10개 조문을 추립니다. 현재 법령군 설정은 최대 3개 법령이며 `cloudflare/evidence-discovery.json`에서 관리합니다. 특정 조문 번호를 정답으로 고정하지 않습니다.
6. AI는 실제 원문 후보 ID 중에서 업무상 의무·권한과 주민등록번호·민감정보 등의 별도 허용 근거를 구분해 선택합니다. 원문 목록 밖의 조문은 채택하지 않습니다. 항목별 필요한 처리 근거 코드는 서버가 연결합니다.
7. 선택한 현행 조·항·호와 개인정보 보호법 연결 근거를 공식 원문으로 검증하고, 별도의 AI 검토가 업무·항목·처리 주체와 대조합니다. 다른 업무·세목이나 정의·분류만 정한 조문은 제외하도록 요청합니다. 모두 not_supported인 후보는 제외하고, needs_information인 항목은 자동 추천하지 않습니다.
8. 출처 목록은 화면에 별도로 표시하지 않습니다. 사용자는 각 근거의 현행 원문과 적용 조건을 보고 선택합니다.

공식 법령 요청별 제한은 30초이며 일시적인 조회 실패는 최대 한 번 재시도합니다. 전체 검색 시간에는 자료 검색·법령 전문 조회·AI 선택·후보별 검토가 포함됩니다.
검색은 관련 발췌와 AI 보고서를 반환합니다. 모든 출처 페이지의 전문을 별도로 내려받아 읽었다고 표시하지 않습니다. 법령 후보를 추릴 때 선택한 개별 법령 전문을 조회하고, 최종 인용 조문도 공식 법령 API 원문으로 확인합니다. 정확한 조문과 업무 적용 여부에 대한 담당자 검토는 필요합니다.

## 비용·제한·설정

공통 설정은 cloudflare/web-search.json에 있습니다. 모델은 OPENROUTER_MODEL을 사용하며 기본값은 openai/gpt-6-luna입니다. 검색 엔진은 도메인 필터와 사용량 제한이 적용되는 exa로 지정했습니다. 검색 호출 최대 3회, 호출당 결과 5건, 총 결과 15건, 결과당 발췌 최대 4,000자이며 검색 단계 대기 제한은 90초입니다. 검색 응답 예산은 8,000토큰이며 gpt-oss 및 OpenAI GPT-5/6 추론 모델에는 low reasoning을 요청합니다. 출력 토큰 한도로 미완료된 경우에만 12,000토큰으로 한 번 다시 요청합니다. 이 경우 추가 검색·모델 비용이 발생할 수 있습니다. 다른 실패는 자동 반복하지 않습니다. 후보 구조화 재시도에는 같은 검색 자료를 재사용합니다. 검색·모델 생성·후보별 검토 비용은 별도로 발생합니다.

서버 도구는 OpenRouter의 베타 기능입니다. 계정 권한·검색 엔진 설정·모델 제공자 지원에 따라 사용할 수 없을 수 있습니다. 제한이 걸리면 계정 설정을 확인해야 하며 도구나 데이터 수집 거부 설정을 제거하는 방식으로 우회하지 않습니다. 입력한 업무 맥락과 항목명은 OpenRouter 및 검색 처리에 사용되므로 실제 개인의 식별값을 입력하지 마세요.

Python 서버는 설정 JSON을 직접 읽으므로 cloudflare 폴더도 함께 보관하세요. Cloudflare는 기존 `npm ci`, `npm run build`, `npm run deploy` 절차로 모듈과 설정을 묶습니다. 새 Secret은 필요하지 않습니다. GitHub 소스 반영과 운영 Worker 배포는 별개입니다.

## 검증

`npm run test:cloudflare`와 `python -m unittest discover -s backend/tests -p test_server.py`는 합성 검색·법령 데이터로 통합 순서, 출처 검증, 오류·캐시·업무 관련성 처리를 확인합니다. `backend/tests/worker-runtime.cjs`는 실제 workerd의 fetch로 Responses API 요청 형식을 검증하되 외부 응답은 합성 데이터입니다. `frontend/tests/browser.cjs`는 웹 검색 출처 목록이 표시되지 않는지와 기존 직접 등록·내보내기를 확인합니다.

본인의 키로 실제 검색 품질을 확인하려면 `python backend/tests/live_api.py --search`를 실행하거나 강사료·자문료·진료 사례를 화면에서 비교하세요. 이 명령은 여러 유료 API 호출을 실행할 수 있습니다. 자동 테스트 통과는 실제 API 인증이나 법률 검색 정답률을 입증하지 않습니다.

공식 문서: https://openrouter.ai/docs/guides/features/server-tools/web-search

## 실패 안내

화면에서는 ‘AI 근거 검색’으로 안내합니다. `/api/status` 200은 서버 상태 조회 성공이며 실제 검색 성공을 의미하지 않습니다. 검색 응답이 실패·미완료이면 502와 고정된 문의 코드를 표시합니다. `output_limit`은 출력 한도, `tool_limit`은 도구 호출 한도, `provider`는 모델·제공자·도구 지원, `balance`는 잔액, `rate_limit`은 호출 한도, `incomplete`는 기타 미완료, `service`는 기타 서비스 실패입니다. 원문 오류에 키나 입력이 들어갈 수 있어 외부 응답의 임의 메시지는 표시하지 않습니다.

실제 실패 응답이나 API 키 없이 이번 오류의 정확한 원인을 특정할 수는 없습니다. 출력 한도 복구 후에도 실패하면 화면에 표시된 문의 코드로 원인을 좁힐 수 있습니다. 미완료 답변이나 출처 없는 결과를 검증된 근거로 사용하지 않습니다.
